# Proposal

## Why

Без подтверждённой доступности и глубины истории действий Trello нельзя достоверно считать Lead Time, Cycle Time и возвраты багов за прошлые периоды. Текущее состояние карточки не является источником прошлого. Нужен блокирующий research-этап до аналитического движка и Dashboard.

## What Changes

- Провести техническое исследование Trello API на предмет истории actions.
- Зафиксировать доступные типы событий, пагинацию, глубину истории, поведение для архивных карточек, rate limits и ошибки.
- Проверить подходы к идемпотентности повторной загрузки и возобновлению импорта (на уровне эксперимента / прототипа, без production analytics).
- Сформировать матрицу «событие Trello → возможность расчёта метрики».
- Описать ограничения, которые система должна показывать пользователю.
- Сохранить результаты в `docs/trello-integration.md` и при необходимости в `docs/trello-history-spike-results.md`.

**Вне scope этого change:**

- полноценный analytics engine и формулы метрик в коде продукта;
- Dashboard и графики;
- массовая реализация sync/API/auth модулей;
- изменения production Nginx/systemd;
- утверждение глубины истории без эксперимента.

## Capabilities

### New Capabilities

- `trello-integration`: требования к исследованию, документированию и ограничениям интеграции с одной доской Trello до построения аналитики на истории событий.

### Modified Capabilities

- (нет — базовых спек ещё нет)

## Impact

**Затронутые репозитории:**

- `trello_analytics_open_spec` — документация результатов, OpenSpec artifacts.
- `trello_analytics_back` — только минимальный исследовательский прототип клиента Trello (опционально/по tasks), без аналитического движка.
- `trello_analytics_front` — **вне scope** (UI не требуется для spike).

**Системы:** Trello REST API (read-only исследование).  
**Зависимости:** учётные данные Trello только через env, не в Git.
