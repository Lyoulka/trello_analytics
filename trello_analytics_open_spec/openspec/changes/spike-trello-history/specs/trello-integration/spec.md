# Spec Delta

## Purpose

Описывает требования к исследованию и документированию интеграции с одной доской Trello, включая доступность истории действий, ограничения API и правила явного отображения пробелов данных до построения аналитического движка.

## ADDED Requirements

### Requirement: Исследование доступности истории Trello до аналитики
Система MUST завершить документированное исследование Trello API (типы actions, глубина истории, пагинация, архивные карточки, ошибки и лимиты) до реализации расчёта исторических метрик на этих данных.

#### Scenario: Блокировка аналитики без результатов spike
- **WHEN** результаты исследования истории ещё не зафиксированы в проектной документации
- **THEN** исторические метрики (Lead Time, Cycle Time, reopen) MUST NOT считаться готовыми к реализации как достоверные

#### Scenario: Фиксация результатов
- **WHEN** исследование завершено
- **THEN** выводы MUST быть сохранены в `docs/trello-integration.md` (и при необходимости в отдельном отчёте эксперимента)

### Requirement: Документирование типов событий и матрицы метрик
Исследование MUST перечислить проверенные типы/сценарии событий Trello и заполнить матрицу соответствия «событие → возможность расчёта метрики» без утверждений, не подтверждённых экспериментом.

#### Scenario: Матрица после эксперимента
- **WHEN** эксперимент по типам actions выполнен
- **THEN** документация MUST содержать матрицу с оценками `да` / `частично` / `нет` / `нужна доп. интерпретация` для ключевых метрик

#### Scenario: Неподтверждённые утверждения запрещены
- **WHEN** тип события или глубина истории не проверены
- **THEN** документация MUST помечать статус как неподтверждённый, а не как доступный

### Requirement: Проверка пагинации, глубины и архивных карточек
Исследование MUST проверить постраничную загрузку actions, доступную глубину истории и доступность действий для архивных карточек, зафиксировав фактические ограничения.

#### Scenario: Пагинация
- **WHEN** объём actions превышает одну страницу ответа API
- **THEN** исследование MUST описать механизм продолжения загрузки и наблюдаемые лимиты

#### Scenario: Архивные карточки
- **WHEN** на доске есть архивные карточки
- **THEN** исследование MUST зафиксировать, доступны ли их actions и с какими ограничениями

### Requirement: Идемпотентность и возобновление импорта на уровне эксперимента
Исследование MUST проверить, что повторная загрузка одних и тех же actions может обрабатываться без дублирования по внешнему идентификатору события, и что загрузку можно возобновить после остановки, сохранив прогресс курсора/страницы на уровне прототипа или описанного алгоритма.

#### Scenario: Повторный прогон
- **WHEN** один и тот же набор actions загружается повторно
- **THEN** результат эксперимента MUST подтверждать возможность дедупликации по `trello_action_id` (или эквиваленту) без искажения набора уникальных событий

#### Scenario: Resume
- **WHEN** загрузка прервана и запущена снова
- **THEN** исследование MUST описать, как продолжить с сохранённой позиции без полной повторной выгрузки с нуля (если API это позволяет) либо явно зафиксировать ограничение

### Requirement: Явные ограничения для пользователя
Документация интеграции MUST перечислить ограничения и пробелы данных, которые продукт обязан показывать пользователю (ранняя/поздняя дата событий, недостаточность истории для периодов/метрик, ошибки импорта, устаревание sync).

#### Scenario: Список ограничений готов
- **WHEN** spike завершён
- **THEN** `docs/trello-integration.md` MUST содержать конкретный список ограничений для UI/статуса импорта, основанный на результатах эксперимента

#### Scenario: Запрет подмены данных
- **WHEN** часть истории недоступна
- **THEN** документация MUST запрещать подстановку предположительных дат или выдуманных событий в расчёты
