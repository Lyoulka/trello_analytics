# Spec Delta

## Purpose

Обеспечивает загрузку и периодическую синхронизацию одной доски Trello в PostgreSQL с пагинацией, возобновлением, идемпотентностью и наблюдаемым статусом качества данных.

## ADDED Requirements

### Requirement: Первичный импорт сущностей доски
Система MUST импортировать для выбранной доски lists, cards (включая архивные при доступности API), members, labels и доступные actions, сохраняя внешние идентификаторы Trello.

#### Scenario: Успешный первичный прогон
- **WHEN** sync запускается при пустой или частично заполненной БД
- **THEN** доступные сущности MUST сохраняться в PostgreSQL без обращения frontend к Trello

#### Scenario: Одна доска
- **WHEN** сконфигурирована доска
- **THEN** импорт MUST работать для одной выбранной доски v1

### Requirement: Идемпотентность событий
Повторная обработка того же Trello action MUST NOT создавать дубликат строки; уникальность обеспечивается по `trello_action_id`.

#### Scenario: Повторный sync той же страницы
- **WHEN** одни и те же actions загружаются повторно
- **THEN** число уникальных `trello_action_id` в БД MUST остаться без дублей

### Requirement: Resume после прерывания
Импорт MUST возобновляться с сохранённого курсора после остановки или ошибки, не требуя полной выгрузки с нуля, если API позволяет продолжение через cursor/`before`.

#### Scenario: Продолжение с курсора
- **WHEN** sync прерван после N страниц actions и запущен снова
- **THEN** система MUST продолжить с сохранённого курсора и не потерять уже сохранённые события

#### Scenario: Пустая доска завершает primary backfill
- **WHEN** board actions API возвращает 0 actions и sync завершается успешно
- **THEN** система MUST сохранить строку `sync_cursors` для `board_actions` и `primary_import_incomplete` MUST быть `false` после success

### Requirement: Инкрементальный sync без head catch-up (v1)
Повторный sync после завершённого primary backfill MUST обновлять сущности доски; MUST NOT подтягивать новые head board actions (курсор остаётся на oldest / NULL).

#### Scenario: Повторный sync не догоняет голову ленты
- **WHEN** primary backfill завершён и в Trello появились более новые actions
- **THEN** v1 sync MUST NOT загружать эти head actions; статус MUST предупреждать о возможном отставании журнала от live Trello

### Requirement: Журнал и защита от параллельного sync
Каждый запуск MUST отражаться в журнале sync runs; система MUST предотвращать одновременные конфликтующие sync одной доски.

#### Scenario: Повторный start во время running
- **WHEN** sync уже выполняется и поступает новый запрос на start
- **THEN** система MUST НЕ запустить второй конфликтующий процесс (отказ или no-op с явным статусом)

#### Scenario: Запись результата run
- **WHEN** sync завершается успешно или с ошибкой
- **THEN** run MUST сохранить статус, счётчики и summary ошибки без утечки секретов

### Requirement: Статус качества данных
Система MUST предоставлять статус: время последней успешной синхронизации, earliest/latest импортированного события (если есть), counts карточек/actions, ошибки/пропуски и признак незавершённого первичного импорта.

#### Scenario: Чтение статуса
- **WHEN** клиент запрашивает статус sync
- **THEN** ответ MUST включать last success и агрегированные показатели качества без токенов Trello

### Requirement: Ошибки API и отсутствие подмены данных
Временные и постоянные ошибки Trello API MUST логироваться и отражаться в статусе; отсутствующая история MUST NOT подменяться предположительными датами или выдуманными событиями.

#### Scenario: Недоступность истории
- **WHEN** API не отдаёт часть истории
- **THEN** система MUST сохранить только полученные события и пометить ограничение в статусе/доках

#### Scenario: Секреты в логах
- **WHEN** происходит ошибка авторизации Trello
- **THEN** логи и status MUST NOT содержать key/token в открытом виде
