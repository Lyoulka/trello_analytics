# Spec Delta

## Purpose

Определяет продуктовую схему PostgreSQL для хранения одной доски Trello, карточек, исходных событий, состояния синхронизации, пользователей и настроек приложения с миграциями и документацией.

## ADDED Requirements

### Requirement: Продуктовые таблицы доски и карточек
Система MUST хранить в PostgreSQL сущности одной доски: board, lists, cards, members, labels и связи card–member / card–label, с уникальностью внешних идентификаторов Trello.

#### Scenario: Уникальность Trello id
- **WHEN** выполняется повторная вставка записи с тем же `trello_*_id`
- **THEN** БД MUST отклонить дубликат через UNIQUE-ограничение (или эквивалентный upsert на уровне приложения поверх UNIQUE)

#### Scenario: Связь карточки с доской и списком
- **WHEN** сохраняется карточка
- **THEN** она MUST ссылаться на существующую доску и, если list известен, на существующий list через внешние ключи

### Requirement: Неизменяемое хранение исходных событий
Система MUST хранить действия Trello в таблице исходных событий с уникальным `trello_action_id`, типом, датой события и при необходимости raw payload; исходные события MUST NOT удаляться или перезаписываться при пересчёте метрик.

#### Scenario: Повторный импорт того же action
- **WHEN** событие с уже сохранённым `trello_action_id` поступает снова
- **THEN** в таблице MUST остаться одна запись с этим идентификатором

#### Scenario: Пересчёт не трогает сырые события
- **WHEN** изменяются формулы или правила workflow
- **THEN** исходные записи событий MUST сохраняться без изменения содержимого

### Requirement: Состояние синхронизации в схеме
Схема MUST включать таблицы журнала запусков синхронизации и курсоров прогресса импорта (resource type, cursor value, last success), чтобы последующий sync мог возобновляться и аудироваться.

#### Scenario: Курсор и журнал существуют
- **WHEN** применены продуктовые миграции
- **THEN** в схеме MUST существовать таблицы для `sync_runs` и `sync_cursors` (или эквивалентные имена с тем же назначением)

### Requirement: Пользователи приложения и настройки
Схема MUST включать таблицу пользователей приложения с ролью и безопасным хранением пароля (hash) и таблицу настроек приложения; секреты Trello MUST NOT храниться как открытый текст в общедоступных настройках без отдельного защищённого механизма.

#### Scenario: Пользователь с ролью
- **WHEN** создаётся запись пользователя приложения
- **THEN** запись MUST содержать email, роль и признак активности

#### Scenario: Секреты не в открытом value настроек
- **WHEN** документируется или реализуется хранение Trello credentials
- **THEN** MUST быть отделено от обычных `app_settings.value` в открытом виде либо явно запрещено хранение plaintext token в этой таблице

### Requirement: Время UTC и миграции
Все временные отметки в хранилище MUST сохраняться в согласованном UTC-формате; изменения схемы MUST поставляться через версионируемые миграции golang-migrate, воспроизводимые из чистого состояния после bootstrap.

#### Scenario: Миграции up на чистой БД
- **WHEN** применяются все up-миграции после bootstrap
- **THEN** продуктовые таблицы и ограничения MUST создаваться без ручных SQL вне миграций

#### Scenario: Откат одной миграции
- **WHEN** выполняется down последней продуктовой миграции
- **THEN** соответствующие объекты MUST удаляться предсказуемо без повреждения bootstrap extension

### Requirement: Документация модели данных
Проект MUST содержать `docs/database.md` с описанием таблиц, ключей, индексов и правил хранения времени/сырых событий.

#### Scenario: Документ после миграций
- **WHEN** продуктовая схема добавлена
- **THEN** `docs/database.md` MUST отражать актуальные таблицы и ограничения целостности
